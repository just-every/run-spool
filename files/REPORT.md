## Implementation and boundaries

- `src/auth/mail.server.mjs` exports the same suppression predicate used by the sender; Members receives that state through its existing access response. Address domains never determine suppression.
- `src/domain/members/local-invitations.ts` captures the exact token from the message submitted to the suppressing sender. The encrypted copy uses AES-GCM, the existing installation secret with purpose separation, and origin/invitation/issuer additional data. Native `oa_tokens` remains authoritative.
- `spool_local_invite_links` is an additive custody table tied to the existing invitation, issuer and native token. Disclosure requires the explicitly local runtime, the inviting current owner, and a still-valid pending native invitation. Accepted, expired or revoked tokens are not exposed. Private archives exclude custody rows; native token deletion cascades and owner erasure includes this table. Project erasure explicitly retains organization-scoped custody.
- `src/ui/workbench/Members.tsx` contains the local notice and copy control. The verification action still uses the existing email-proof request. No hosted invitation, role, step-up or transfer rule changes.
- `AGENTS.md` documents the local flow. CONTRACT.md, ACCEPTANCE.md and docs/CLAIMS.md are unchanged. Generated deployment integration and sources.lock.json are regenerated by their documented commands.
