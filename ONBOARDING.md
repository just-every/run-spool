# Spool local onboarding

Use Node 22 or later and git (without Node, `curl -fsSL https://runeditrun.com/install.sh | sh -s -- setup just-every/run-spool` brings its own). rer supplies the declared Node 22.20.0 and pnpm 10.12.4 runtimes. One line clones Spool, installs frozen dependencies and claims the first owner with your email; then, from the checkout, validate the command contract and start the private workbench:

```sh
npx -y @runeditrun/rer setup just-every/run-spool
cd run-spool
rer check --profile first-party
rer dev
```

Setup applies additive D1 migrations to local storage, generates managed secrets in the ignored 0600 `.dev.vars`, claims one real owner through operator-auth and stops its temporary app. It preserves existing owner identity and secrets. Open the private `RER_OPEN` link printed by `rer dev` to enter as the owner. Its `rer-dev` fragment value is this checkout's private owner gate. Dev and demo silently suppress mail and expose no mailbox viewer; no email confirmation is needed locally. See [OPERATIONS.md](OPERATIONS.md) before recovering an older installation. After sign-in, create one or more project scopes and save each ingest key when shown because it is not displayed again. Register the project's release and build before capture; upload a matching flat Source Map V3 file when original source locations are needed.

With rer dev v2 (pinned rer 0.2.22), the ingest key works from your application against local Spool without the owner gate. Allow your browser app's exact origin in Capture. A local deploy key can register releases and upload maps without the gate. Dev-minted agent keys still require it: privately extract the `rer-dev` fragment value as `SPOOL_DEV_KEY` for trusted local agent CLI/MCP use, invoking the CLI by its absolute path inside the Spool checkout even from your app repository. Never give that gate to a browser app or include it in source or build output. Deployed Spool refuses every dev-minted key; sign in there and create fresh keys. See [key scopes](docs/capture.md#keys-for-anything-outside-this-checkout) and [private agent setup](docs/WITH-YOUR-AGENT.md#local-agent-access).

For non-interactive setup, save `{"OWNER_EMAIL":"you@example.com"}` in the ignored `.rer/local/setup-answers.json` with mode `0600`, then run `rer setup --answers .rer/local/setup-answers.json --non-interactive` from the Spool checkout. The file must be owned by you and the path relative and contained inside that checkout, with no traversal, symlinks or shared hard links. See [installation](docs/install.md#install-and-start) for the file procedure. Keep addresses and secrets out of shell arguments.

The installation has one owner identity. Ingest keys write only to their project, and read-only agent grants expose evidence only from their project. Accepted events are allowlisted and pattern-scrubbed before D1 storage. Inspect free text and packet previews before sharing because pattern scrubbing cannot identify every secret or personal detail. Maps and archives are private; archives exclude owner/auth records, sessions, grants and local settings. Restore requires an empty domain database. Preview retention before applying it: deleting events also deletes retry identities before the selected cutoff. Reaccepted event IDs and reuploaded map keys receive new occurrence identities; permanent erasure records continue to protect the deleted occurrences.

A fresh local database has no telemetry fixtures. All event, project, map, and archive data you add is stored in your local D1 state. Setup, development, and verification make no remote resource or provider calls. Stop development with `rer dev --stop` before transfer, reset or switching to preview. `rer deploy --dry-run` builds and validates the actual Worker/assets package without provider calls. Actual deployment requires separately authorized owner-account inputs and mail sender configuration; follow [OPERATIONS.md](OPERATIONS.md). Local checks do not prove hosted deployment or mail delivery.
