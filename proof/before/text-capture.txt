Set up original-source mapping

A source map connects a built JavaScript file’s line and column to the same code in your original source.

Run these steps in your application’s repository before deploying its built files. The tool generates a debug ID, stamps that same ID into the bundle and its map, registers the release and uploads the map. You do not need to invent or enter an ID.

Each bundle needs its adjacent .map. Deploy the stamped output after upload; rebuilding afterwards removes its matching ID. Keep maps private when publishing assets.

4. Confirm a mapped frame

The CLI prints the uploaded map count. The published SDK 0.1.0 Vite/Rollup plugin is silent on success; an upload failure fails the build. Trigger a new error in your deployed application, open its issue in Spool, then look for Original source and a frame such as src/checkout.js:7:12. Spool’s own test exception checks capture only, not your app’s maps.

If the frame is still unmapped
No event: allow the app’s exact scheme, host and port on Capture, and check its ingest key and registered release.
Upload refused: check the deploy key belongs to this project and installation, and is exported as SPOOL_DEPLOY_KEY. CLI uploads accept flat or indexed V3 maps up to 1 MiB each, without a lifetime map count. Check the project byte cap above. The prepared-map picker below retains its smaller flat-map limit.
Missing map or debug ID: confirm the served bundle ends in //# debugId=… and its adjacent map’s debug_id matches. Deploy those exact stamped files, clear old cached bundles and trigger a new error.
Map uploaded but no original location: match the event’s project, release and build exactly; include every chunk’s map and check the map contains mappings for the failing line.
