# Spool issue browsing

The dedicated Issues view uses the existing approved layout and real retained groups. Search, filters, counts, facets and ordering now run over the full project corpus through the versioned, authorized investigation API. Each page contains 25 groups; cursor order is active attention, latest receipt or occurrence count, with deterministic receipt/ID ties. Browser-local unseen facts describe only the current page and do not acknowledge an issue.

Search and export semantics, supported fields, bounds and permission rules are in [INVESTIGATION.md](docs/INVESTIGATION.md). All occurrence predicates in a query must match one occurrence. Counts shown on a matching group remain its whole retained occurrence count. JSON/CSV exports either include every matching group within the documented bound or refuse the query explicitly. The older array issue API remains available to existing clients with its original 100-row bound.

The public-door flow in `tests/investigation-flow.mjs` creates 108 groups, traverses every page, finds an older group with combined filters, reconciles facets/exports and denies wrong-scope reads. Its rendered journey exercises filtering, pagination, download and empty-result recovery at 1440 and 390. The run brief additionally requires screenshots from `rer dev` before landing. Full team/identity/tag search, collaborative review and shared saved views remain contract gaps.
