# Project inbound filters

Settings exposes server-side inbound filters for browser extensions, legacy browser versions, localhost/loopback, the published crawler user-agent catalogue, React hydration, chunk/dynamic import failures, IPv4/IPv6 addresses/CIDRs, message patterns, releases, environments and exact/wildcard browser domains. New projects start with extensions and crawlers on; each default can be disabled. Localhost is off so a local application's first capture remains usable.

Each filter shows its last-24-hour match count. Preview pages through the entire retained corpus; missing historical transport metadata is explicitly unavailable, including all client IP addresses. Settings aggregates every preview page before allowing Save. Policies use revision checks and same-origin owner authority; the admission transaction fences that exact policy. A concurrent change refuses stale intake rather than storing under a different policy.

Matching native and Sentry error events create no issue, occurrence, alert or accepted-usage unit. They count once as filtered plus once per matched filter (per-filter totals may overlap). Browser domain refusals return 403 without a CORS grant. Both Origin and Referer are checked; legacy exact browser origins and the installation origin remain allowed. Server/native requests without browser headers remain usable. Client address matching uses Cloudflare's connecting-IP header, never an untrusted forwarded-for header.

`GET /api/projects/:project/inbound-filters`, `POST .../preview` and `PUT ...` independently require the owner. The policy is private archive content and participates in project erasure; permanent audit records a policy digest and revision rather than filter values. Older archives gain an empty policy table and use the published defaults. Owner self-erasure refuses unsupported policy attribution when it finds the owner's identifier.

Message, release and environment patterns support literal text and `*`, without executing regular expressions. The current intake/wire limits and registered-release rule remain; commercial USD billing, budget forecasts, spike protection, DSN key limits and client-report accounting remain contract gaps. Recent accepted/filtered figures are admission usage, not an invoice.
