# Alert implementation boundaries

The edition owns `src/domain/alerts` and `src/ui/alerts`. Portable Base integration runtime files under `src/modules/integrations/core` are copied unchanged from Base at the revision recorded in `base-copies.json`, together with its additive schema migration. The Worker imports portable core modules individually; Unused Node DNS/HTTPS and SQLite transport files are not copied into the Worker source tree. Base mail is the exact shared runtime adopted by Wave A under `scripts/base-cli/modules/mail`; sign-in and alerts use the same sender configuration and development outbox.

A delivery ID is `<alertId>.<ruleId>.<revision>`, persisted with exact body and destination version in the admission transaction. Spike alert IDs derive from rule ID/revision, issue and aligned window. `alerts.payload` contains immutable transition release facts for the triage UI; it must never be replaced with a latest-release lookup. Historical alerts migrated from earlier source have a null payload and are never routed.

The actual Worker scheduled handler calls `runAlerts`; Wrangler invokes it every minute, and each call records `alert_scheduler.last_run`. New-issue and regression intents are also dispatched right after their admission (`dispatchAdmitted`, through `waitUntil`); the scheduled run picks up anything that dispatch left queued. Catch-up is bounded to four complete windows per rule per invocation, twenty due rules, and thirty due dispatches per project/channel. Retained event capacity and rule capacity bound one window's fan-out. Cursors resume remaining backlog rather than skipping it. A missing production enforcing egress binding is a visible configuration block. The local test-only adapter is outside the production import graph and maps only a fixed synthetic public HTTPS destination to a real loopback receiver.

Local tests prove application policy, durable admission/claims, real signed byte transport and receiver replay storage. They do not qualify a deployment-owned egress service's DNS pinning, TLS, caller authentication or target allowlist. Installing/qualifying that service, a mail sender, and live-account/provider acceptance remain owner-held.

Accepted event `received` is assigned by SQLite inside the admission transaction. An HTTP request paused before its batch cannot later add an old received timestamp to an already consumed complete spike window. Feed transition timestamps remain their immutable server-created snapshot.

Expansion traverses each project's pending and blocked intents using a persisted rotating ID cursor. A blocked destination consumes its turn, then other destinations progress on the next page. Due spike rules likewise rotate by durable rule ID while retaining each rule's complete-window cursor and four-window catch-up limit; an old backlog cannot occupy every invocation. These scheduling cursors are operational state and are excluded from archives.

Mail claims start from the current time of each individual job, including its due predicate, attempt timestamp and lease deadline. A webhook request is bound locally to the exact Base claim that prepared it. After consumer configuration and rule authorization have yielded, the adapter checks that same durable sending claim, current rule revision and expiry again; it checks expiry against the clock after the final database round trip before invoking enforcing egress. The binding never changes signed headers or copied Base code.

`issues.latest_release_seq` records a monotonic release watermark when an event is inserted. Resolving snapshots that watermark inside the triage update, so retention cannot make an old release appear new. The migration and native v1/v2 archive conversion conservatively use the registered project release ceiling when old history is incomplete. Earlier Base JSONL archives preserve an explicit unknown watermark: they cannot emit regressions until a fresh admission or owner triage establishes a conservative baseline. Current archives retain the durable value even when all occurrences have been erased. Historical imported groups remain ineligible for alert transitions and spike routing.
