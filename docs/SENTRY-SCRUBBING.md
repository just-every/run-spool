# Server scrubbing rules

The installation owner configures server rules in Project settings. Until TEAM-001 introduces organizations, installation rules protect every project. Project safe fields and custom rules that overlap installation protection are refused; older project policies cannot overwrite a value protected by a later installation rule. Default secret-name masking remains active.

A policy contains additional sensitive fields, exceptions within its own scope, and custom rules. Custom methods run before additional sensitive-field masking within each scope; the installation layer completes before the project layer. Default masking then protects every remaining secret-named field. A custom rule selects a kept field and matches a built-in credit-card, IP, email, password, authentication-token or US Social Security number pattern, or a bounded custom expression. Methods remove the field, mask it, hash it with the project's private key, or replace it. Removing the required native message leaves an empty string. Protocol identities such as release, environment and event identifiers are outside selectors.

Selectors cover `$message`, `$logentry.params`, `$exception.value`, `$frame.vars.order_note`, `$frame.vars.**`, `$frame.context`, `$request.headers.name`, `$extra.key`, `$contexts.key`, `$tags.key`, `$breadcrumbs.message`, `$breadcrumbs.data.key`, `$user.key` and `$log.attributes.key`. Context selection includes every SDK-sent source line. Located Sentry logs retain bounded attributes; generic logs remain refused. A Sentry log batch opts into located admission with `spool.event_id`; it then requires version 2, complete source coordinates and the explicit build/release/environment binding. Missing or invalid opted-in metadata is invalid. Ordinary SDK batches, including versionless batches and partial source coordinates, retain the named unsupported-log outcome. OTLP keeps its existing located-log projection and its message passes through server scrubbing; arbitrary OTLP attributes remain discarded.

Preview scans at most 100 retained events and shows scanned/total coverage, matched-field counts and up to three sample projections. A matched field is replaced wholly with `[matched]`, including aliases. Saving requires that preview's exact draft, project revision and installation revision, within 24 hours. Saves append safe rule identifiers, selectors and methods to audit history, never matched values. Preview tokens are operational and excluded from archives.

Policies apply to later intake before derived issue titles, diagnosis, packets, alerts and storage. They also protect retained user identity values and feedback descriptions. Retained occurrences are unchanged. Sessions and check-ins retain their existing bounded protocol fields rather than arbitrary context. Hashes share the project's private key but use a separate scrubbing domain. Archives carry both policy scopes and change history; project erasure removes its policy, previews and history, and owner erasure removes both scopes.

Custom expressions are limited to 256 characters and candidates to 8192 characters. Backreferences, lookarounds, groups, nested or multiple variable quantifiers, unanchored variable quantifiers and large repeats are refused with a named reason. Text beyond the evaluation bound is refused rather than passed unscreened.
