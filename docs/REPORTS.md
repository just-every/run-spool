# Reports and saved views

Reports live in the workbench’s Reports view; administrators and project maintainers configure dashboards, saved reports and event tables under Settings. A report selects accessible projects or a TEAM-001 project team, explicit UTC window endpoints and an IANA time zone. Daily calendar boundaries follow that zone, including daylight saving. The underlying instant window and totals stay fixed when the zone changes.

Error totals count retained occurrences, including errors without a release. Named-release rows exclude those errors and disclose their count. SDK-008 supplies the one affected-user definition and unattributed-event count; cross-project totals sum project-scoped identities, without joining people across projects. SDK-005 supplies observed session health, its uncertainty and denominators. SDK sampling before receipt is unknown. Each result carries current retention cutoffs, recorded retention gaps and receipt-minute loss counters; overlapping counter reasons must not be added into one loss estimate.

Backlog reconstructs proven native lifetimes from capture history, triage and commit-resolution audit, and regression alerts. Missing, imported, regrouped or inconsistent history is excluded with issue identifiers and reasons. Acknowledge and repair durations measure the first explicit acknowledgement or resolution of a new/regressed cycle within the window. Review alone is separate. Resolution time does not establish a successful repair. Incomplete cycles are named rather than treated as zero. Ownership shows current team and assignment responsibility, not historical ownership.

Custom dashboards allow 12 widgets and 25 dashboards per organization, with named server refusals at capacity. Count, observed events/minute and affected-user widgets run the existing FIND-001 event predicates on the same occurrence. Grouping supports environment, release, level or a currently retained non-identity tag key. Session widgets query stored session observations by release, environment and dates, with release/environment grouping. Other predicates are explicitly refused because stored sessions have no event association. That association remains an unproved FIND-002 capability.

Event tables reference the existing saved review-query store and validation; they do not fork its grammar. `issue-search?eventTotals=1` adds a matching-occurrence count for reconciliation; default issue aggregates keep their existing shape and whole-issue counts. Previews disclose their 25-row cap. CSV/JSON exports use the saved query and window, refuse more than 10,000 rows or 8 MiB, and refuse incomplete grouped-widget exports. Reports additionally bound the project scope and projected source-row count before reading. All refusals ask for narrower scope; no bound silently truncates an export. CSV formula-like text is inert.

Sharing with a project team or organization role grants access to a definition only. Every read and export intersects current project membership, omits inaccessible widgets and reports only their count. An id with no accessible project is concealed as an unknown id. Shared links select a project the viewer can read, so they do not depend on the author’s project selection. Read-only members may export; billing, ingest, deploy, agent and service credentials confer no reporting access. Exports contain occurrence metadata and identity counts, never raw user values, frames or local variables.

Definitions, edits, sharing, shared reads and exports use AUDIT-001 safe aliases. Private archives include definitions and saved-query references with authors erased and all shares inactive. Restore sends nothing and restores no reporting authority. Figures are recomputed from retained data without event-derived caches. Project erasure removes its widgets/references and sole-project definitions; other project widgets survive. Installation-owner erasure clears authors and redacts supported personal text. Removed members lose access at the next door, with in-flight reporting authority fenced before return.
