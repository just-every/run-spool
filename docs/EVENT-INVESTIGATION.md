# Retained event investigation

Issue detail's All Events reader covers the complete retained issue, independently of the agent packet's ten-event and 256 KiB bounds. It uses the issue search predicates for release, environment, time, chain exception properties and every retained tag. Percentages in the tag summary use all retained events in the issue. The summary names its 1,000-value bound.

`GET /api/projects/:project/issues/:issue/events` accepts `q`, `order=newest|oldest` and a query-bound `cursor`, with 25 rows per page. It supplies oldest, latest and recommended identities. Recommendation counts frames and tag/context fields among the latest 100 matching events. `GET .../events/:event?occurrence=:occurrence&q=...` requires exact issue and occurrence membership and supplies the previous/next matching identities, sanitized full event and current source lookup. A retained occurrence's selected identity is reflected in the URL. Both endpoints independently require the owner; read-only agent credentials retain their existing sanitized packet scope.

For admitted Sentry events, Related Exceptions preserves the exception chain and group relationships, SDK-sent source context, masked local variables, tags, contexts and other retained sections. Library frames collapse; traceback-hidden frames stay hidden. Raw stack text can be copied. Primary source-map lookup remains bounded to the existing coordinate projection and is labeled separately. The packet excludes SDK source lines and local variables; rich owner reads do not authorize model egress.

The Sentry admission projection remains subject to the existing wire limits and registered-release rule. Configurable grouping/scrubbing rules, user identity policy, custom dashboards, sessions, team reports, full runtime SDK qualification and large streamed exports remain contract gaps.
