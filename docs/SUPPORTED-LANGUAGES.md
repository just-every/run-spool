# Exception languages

Spool's native `POST /api/ingest/{project}` and Sentry envelope/store intake accept JavaScript, Python and Go exception evidence under the same project ingest grant, browser-origin policy, registered release/build check, admission budgets, deduplication and scrubbing. The browser/Worker SDK, source-map tooling and sandbox reproducer remain JavaScript only. OTLP support is unchanged; it does not accept Python/Go exceptions. No telemetry URL is fetched and no telemetry executes.

For native Python/Go capture, send `version:1`, `language:"python"` or `"go"`, `eventId`, `release`, `build`, `environment`, and either `frames` or `stack` (never both). Structured capture additionally requires `type` and `message`. `breadcrumbs` defaults to `[]`. Structured frames are ordered newest/throw first and require `file`, positive one-based `line`, and `function`. The normalized file path must be nonempty and contain no control characters. A missing or null `column` stays unknown; supplied columns are zero-based. There are 1–30 structured frames. A `debugId` never makes Python/Go eligible for JavaScript source maps or execution, including paths ending in `.js`.

```json
{"version":1,"language":"python","eventId":"checkout-1","release":"1.2.0","build":"server-1","environment":"production","type":"ValueError","message":"quantity rejected","frames":[{"file":"app/cart.py","line":42,"function":"checkout"}]}
```

Raw `stack` strings are limited before parsing to 32 KiB UTF-8, 1,000 lines, and 4,096 characters per line; at most 30 frames survive. The native request body retains its existing bound. Raw Python parsing derives type and message from the final exception summary, overriding supplied type/message. Go derives the message from the panic/fatal-error prefix; an explicitly supplied type is preserved (for example `*runtime.TypeAssertionError` from runtime metadata), otherwise the prefix supplies the default below. A Go current-goroutine stack without a prefix defaults to type `panic` and an empty message. Exception messages are scrubbed and bounded as usual.

Python accepts ordinary CPython `Traceback (most recent call last):` with `  File "path", line N, in function` entries and an exception summary. The header must be the first nonblank line. Frames are reversed to put the throw first; a chained traceback selects the final traceback and exception after CPython's handling/direct-cause separator and next header. Source lines, caret markers, repeated-frame markers, multiline message continuation and PEP 678 notes are discarded. Once the exception summary is reached, location-shaped notes never become frames. A malformed location before that summary rejects the stack rather than promoting its caller. Exception-group displays/types, stackless/syntax-error displays without these frames, and non-CPython display formats are unsupported; ordinary source or messages mentioning exception groups are accepted. Python paths are reported source coordinates, not verified source content or symbolication.

Go accepts `panic:` and `fatal error:` displays and runtime/current-goroutine stacks containing function/location pairs, including Unicode method receivers and generic symbols such as `main.(*Server[...]).Serve(...)`. Runtime diagnostic text before a panic/fatal prefix is discarded. Between the prefix and goroutine headers, multiline message continuation, nested panic prefixes, signal metadata and a valid `runtime stack:` are accepted. Message continuation is discarded; a CPython traceback header followed by Python frame locations is rejected as a foreign stack. It chooses the unique `running` goroutine, otherwise the unique `runnable` goroutine, otherwise the only goroutine when the dump contains just one. Multiple candidates at the selected priority or multiple blocked goroutines are ambiguous and rejected. Frames are already newest first. Every selected function must have a valid positive source line; malformed pairs or foreign stack text reject the stack rather than promoting a caller. Runtime argument lists, addresses/offsets, goroutine metadata, valid `created by` ancestry and other goroutines are discarded. Default panic type is `panic`; default fatal-error type is `RuntimeError`. This is source-path evidence, not binary/DWARF symbolication.

Sentry `platform:"python"` and `"go"` use structured exception stack frames, selecting the last exception and reversing Sentry's oldest-first order. Every supplied frame needs a usable path and positive `lineno`; invalid coordinates reject the event instead of substituting a caller. `colno` may be absent/null, otherwise it is converted from one-based to zero-based. Exception-group events are unsupported. Sentry user, request, extra, locals and source-context fields are discarded. Existing JavaScript behavior and fingerprints remain unchanged. Python/Go fingerprints include language, exception type and the first reported file/function/line, excluding message, release, build, environment and mapped repository path. Equivalent native raw/structured and Sentry locations therefore join the same language-specific issue. Original grouping and admission diagnostics remain immutable when current lookup changes. Retries compare a digest of the raw input; changing even discarded data conflicts under the same event ID.

## Go repository path mapping

An owner or project deploy key can register the existing release manifest with optional `pathMappings`. This synthetic example uses the public Spool repository; its build paths and commit are illustrative:

```json
{"name":"1.2.0","build":"server-1","manifest":{"commitSha":"0123456789abcdef0123456789abcdef01234567","repository":"https://github.com/just-every/run-spool","deployedAt":"2026-10-15T00:00:00.000Z","environment":"production","pathMappings":[{"from":"/build/service","to":"src"},{"from":"/build/service/vendor","to":"third_party"}]}}
```

Mappings bind exact project, release, build and environment to the manifest repository and commit. There are 1–20 unique prefixes, each at most 512 characters. Prefixes use forward slashes, no trailing slash, whitespace/control characters, query/fragment, percent escapes, traversal (`.` or `..` components), or text the privacy scrubber would alter. `to` must be a repository-relative path; the single value `"."` maps to the repository root and is the only dot-component exception. Match the longest complete path prefix, not a partial directory name. File, line and function remain available; mapping changes only the displayed file path. POSIX/Windows home directory names and path queries/fragments are scrubbed before storage and lookup; mappings must use the scrubbed prefix, with `[user]` in place of the username component beneath the POSIX home-directory root or Windows users directory.

A mapping can be added to an already registered manifest. Once recorded it is immutable: repeat the same mapping for idempotent registration; conflicting mappings return conflict. Missing or unmatched mappings remain explicit diagnostics. Later registration enriches current lookup without changing at-admission evidence or grouping. Mappings and provenance travel in private owner archives and project erasure, separately from Source Map V3 artifacts. Import into an empty destination preserves them and creates no credentials. No repository content is downloaded or executed.
