# Spool's triage engineer door

Spool serves one shared agent door at `/mcp`, its OAuth protected-resource
metadata, `/agents`, the native approval pages and `/api/rer/agent-policy`.
It supports MCP `2026-07-28` and `2025-11-25`. Discovery and the
`triage-engineer` prompt describe the supported work. The exact tool and scope
inventory is generated in [AGENT-TOOLS.md](AGENT-TOOLS.md).

A triage engineer can inspect a captured failure, packet and capture-loss
context; save an inert grouping proposal; prepare a native deterministic
reproducer and request its bounded sandbox grant; record a repair claim and
read independent recurrence and release evidence. Native GitHub workflows
prepare a **draft data PR** containing a reproducer JSON file. They do not
generate a source repair, merge, deploy or execute a GitLab workflow.
An absent sandbox result, repository connection or exact repository consent
remains unavailable. A recorded deployment never performs a deployment.

## People and authority

The existing installation owner-claim issuer, installation ID, application
origin and public ring authorize Business access. Signed Business settings at
`/api/rer/business-settings` bind `owner_id` and team-entry `id` to native
operator IDs. Subsequent authorization uses those IDs, never a token email.
Existing settings without Business IDs remain valid but cannot authorize an
unmapped person.

The team adapter maps the signed roster to existing native Spool members.
Native enrollment and current project grants remain necessary. It does not
create project access or promote a member from a Business role. A reused email
cannot take over an established binding. Inactive, removed and conflicted
mappings refuse authorization. Business owner/editor policy roles remain
separate from native organization and project permissions.

The native services re-read current operators, memberships, project grants
and revisions. Execution uses an in-process agent principal, never a borrowed
person session. Project client keys keep their exact project and original
read/proposal scope; they cannot apply grouping, manage members, obtain a
sandbox grant or call GitHub. Narrowing and removal permanently retire affected
keys. A later promotion does not revive them. Private loopback development
admission remains necessary for development-minted agent keys.

The stdio client retains its five compatibility names and proxies the shared
registry. Retained project evidence/proposal REST routes enter the same policy
pipeline. Ingest, deploy, runner, provider, import and installation credentials
retain their separate native purposes.

## Policy and outcomes

The company supplies autonomous, review, approval or blocked dispositions.
An unset, unanswered or expired policy refuses agent work. Business or local
Pause stops the next agent effect; people retain their native access. No policy
or caller confirmation grants additional native authority. Approval binds the
saved action summary, policy revision and summary hash. A stale decision runs
nothing. The agent remains the preparer; actual people are recorded separately
as approvers.

An inert proposal is standard work and does not apply grouping or suppress
alerts. Suppression and active grouping changes are live effects. Credentials
and membership changes have security/access classes derived from the current
native target. Shortening retention adds destructive risk. Recording a repair
or an asserted passing check does not become independent proof. Quiet or lost
telemetry remains inconclusive.

Primary resources use `spool://projects/{project}/…` and return bounded native
projections. Packets, logs, imported text and repair notes are untrusted data.
Resources do not reveal bearer credentials, source-map bytes or source code.
A bounded sandbox grant is issued only by its dedicated native request tool;
the runner still consumes it once and reports observations through its machine
door. A queued request is not a successful reproduction.

Agent repair records name the agent for the sponsor in native repair history.
The shared door retains policy audit, approvals and access-filtered events;
native person edits emit the same resource vocabulary. Agent-modified alert
rules retain the originating sponsor, agent, client scopes and Business consent
for typed admission at notification dispatch. Agent retention and alternate-notice settings likewise retain their original principal for typed worker admission. Provider uncertainty keeps its
native custody and is never treated as permission to resend.

## Current integration boundaries

Runtime source is recorded at Base
`7ce44fa5b70b68b21d270ba54760dae28b4a37a7`. The installed CLI remains separately
pinned in `package.json`; the matching unreleased Base CLI must run conformance
until its npm release is available. Generate the surface with
`node scripts/agent-surface.mjs`; check it with the same command and `--check`.

The pinned Base head has pending native-target audit, resource error-code,
mutation replay admission, project-scoped revoke-only conformance and reviewer
lifecycle assertions. They remain dated assertions in the agent test. The
normal conformance declaration also retains every tool/class pair, including
provider and queued actions; unavailable native/provider setup must fail the
journey. The generic verifier needs a declared synthetic GitHub connection
binding and a way to drive native machine triggers between policy phases.
No provider completion is implied by the test edge.

Project erasure holds while unattributed shared agent custody exists, rather
than claiming it removed history that the current Base target contract cannot
select safely. Installation-owner erasure likewise retains its existing
unsupported-surface refusal. Source locks, applied migrations and retained
audit are not bypassed. Contract status promotion waits for the separately
owned Agent surface rewrite and complete native/CLI proof.

Spend caps are **not enforced** by this Base continuation. Native quotas,
recipient consent, repository consent and isolated execution still apply.
Spool provides no money-moving tool, general code repair, automatic merge or
production deployment authority.
