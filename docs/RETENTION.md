# Project retention

Settings → Retention windows gives the owner separate windows for event occurrences, unreferenced source maps, feedback, exposure observations, commit author/message text and individual SDK sessions. Each is 30–90 whole days, default 90. Commit SHAs and links remain; session aggregates have no automatic expiry in this slice. Individual sessions use their stored SDK update timestamp; other cutoffs use the server receipt/creation or last exposure time.

Preview windows shows selected counts, oldest/newest timestamps, the cutoff coverage gap and an approximate stored-byte estimate. The estimate counts stored text plus estimated structured rows, excluding indexes, database overhead and aggregate storage. It is not a price. Shortening any window requires the exact typed confirmation `SHORTEN RETENTION` and the current preview token. Changes are owner-only, revision-fenced and audited. Saving windows changes future expiry; it does not silently apply the legacy one-time cutoff.

A legal hold requires a reason to set or release. It pauses every retention deletion, including the manual cutoff and scheduled runs, and appears in Settings and the issue packet. The private reason stays in owner data and the private operational journal; the agent packet states hold status without the reason. A hold never blocks project or installation-owner erasure. Policy and hold are included in private archives, restored under validation and deleted by erasure.

Scheduled expiry runs daily per project through the existing cron handler. Each visit processes at most 50 occurrences, standalone feedback reports, exposure rows, commit text records and individual sessions; at most five projects are visited per cron. Pending work resumes next cron; completed daily runs are idempotent. A short lease prevents duplicate workers. Held projects are skipped. Each destructive batch uses the same `applyRetention` path, occurrence/checkpoint tombstones, deduplication horizon and named retention gap as the owner cutoff, with the service actor `scheduled retention`. Settings shows the latest execution status and remaining rows. The execution cursor is local operational state, excluded from archives and removed by erasure.

Automatic source-map and session-aggregate expiry remain absent; source maps can be removed by the explicit owner cutoff only when no retained event references them. The one-time cutoff remains available in Settings, with its preview and explicit confirmation. Receipt retries before an erased cutoff can be admitted again; comparisons across a cutoff are incomplete.

Residency selection, commercial plan windows, admission-cap changes, sustained 6,000/minute intake, streaming archives, the 160,000-event run and aggregate/artifact automatic expiry remain gaps. Existing 120/minute and 10,000-retained-event admission limits are unchanged.
